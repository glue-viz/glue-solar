## Decisions settled on 2026-09-27 (write these into the plan; do not re-litigate)

- D1 (restated): keep `link_hpc` permanently. It supplies exact, per-frame, time-aware world coordinates and world-component subsets. APE-14 `WCSLink` (core #2595) supplies frame-0 pixel paths (ROIs, Pixel markers, overlays), and in glue the 1-hop WCSLink always wins pixel paths. Drop the 186/187 and 14/187 reach numbers (they came from a now-forbidden all-ones matrix + lambda link, and from irispy 0.8.1's 10x-wrong SJI CDELT fixture). Keep the measured 42.2 arcsec drift over 4.8 h. Never add an SJI world-time link.
- D2 (amended): implement in glue-solar through public registries. Temporary workarounds are switched on by behaviour probes, not version numbers. Each names the upstream fix whose release removes it, and pyproject floors change only when a release contains the fix. A private-method patch is allowed only if gated, tested and listed in WP0 with its upstream PR (Profile restore priority, Pixel crosshair visibility, physical aspect).
- D3 (scope extended by the user): arcsec for helioprojective axes and Angstrom for wavelength apply to `_GlueWCS` IRIS data and ALSO to glue-solar's own sunpy Map loaders (`glue_solar/sources/maps.py` and `sources/loaders/maps.py` get wrapped in `_GlueWCS` in WP1, M1), so `link_hpc` covers File→Open maps.
- D4: moments and fits are dataset `layer_action`s that add data and links, not viewers.
- D5: M0 runs on the released baseline: glue-core 1.27.0, glue-qt 0.4.2, irispy-lmsal 0.9.0 (the new micromamba env `iris-plan`). No unreleased PR is an M0 prerequisite.
- D6: M0 selection uses the stock Pixel tool (click/drag follows, release holds) plus an explicit 'Clear point'. M1 adds a hover-follow + click-lock tool.
- D7 (M0 coordination defaults): fixed detector pixel (no world tracking from the scan-0 stack WCS); index axes plus timestamp readouts (a sit-and-stare time-axis adapter is an M1 item); nearest-exposure ties go to the earlier exposure; NO MATCH when |offset| > half the partner's median cadence or the time is outside the partner's coverage: the partner panel is greyed and shows the offset, never a clamped frame; master = the raster by default, switchable to an SJI through a visible control.
- D8: WP4 time sync uses NO glue links in M0. A coordinator reads 1-D nearest-index/offset arrays derived from each dataset's `Time` and moves sliders itself. It never resolves `data[other_pixel_cid]` through the link graph. Links from main components into pixel component IDs are forbidden. Design B (nearest-index components linked to plain 'Exposure index'/'Frame index' components) is allowed later only if time-gated subsets are wanted, and only with the combined-graph permutation regression.
- D9: coordination is implemented as registered viewer tools (the `solar:frame_time` pattern) plus one coordinator per DataCollection. The tools are instantiated for restored viewers too. Never wrap `app.new_data_viewer`.
- D10: negative-step (STEPS_AV < -0.01) rasters keep irispy's default orientation. glue-solar derives mask/NaN from the (flipped) data values, reverses per-step meta itself, and `nearest` handles unsorted/duplicate references (np.unique first-index semantics). irispy `revert_v34=True` is the documented alternative. WP0 reports the irispy mask/meta bug.
- D11: rest wavelength = explicit override, else the packaged line-list laboratory (vacuum) value matching the window (the user picks for multi-line windows such as C II 1334/1335 and Mg II k/h), else none. Never TWAVE silently (the Mg II k window TWAVE is off by about 16 km/s). No km/s for continuum windows. Stored as a float `meta['rest_wavelength']` in Angstrom so it survives sessions.
- D12: IRIS fill values -200 AND -199 count as missing (NaN), following IRIS-SSW (`iris_make_fits_level3` NaN-fills r < -198.5; `iris_raster_browser` uses missing=[-200,-199]). Saturation is +Inf per ITN26. Masks are stored as uint8 (bool is coerced to int64 by glue).
- D13: sessions: the Quantity saver is registered only if none exists, and a small core PR adds it upstream. WP3 is ported as `_GlueWCS.__gluestate__/__setgluestate__` methods and named factory functions, never by importing prototype modules.
- D14: irispy `gwcs_raster_clean` (the user's branch): track only. WP0 gate: do not propose it until the glue-solar loader accepts both APIs. M0 stays on irispy 0.9.0.
- D15: the preset uses an MDI tab with explicit viewer geometry, not the experimental fixed-layout tab (which breaks app.viewers and is not restored).
- Adopted by default (the user can flip these later; mark them "default, confirm" in the plan): SJI/SJI links under #2595 → amend #2595 (the user's own draft) so autolinking leaves time axes out, with WP4 matching authoritative for time. SJI<->raster when WCSLink and link_hpc coexist → keep both, document frame-0 pixel geometry, and let the coordinator translate SJI clicks through per-frame WCS/Time (this path works on released core).
